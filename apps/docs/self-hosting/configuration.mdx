This page is for operators. All settings live in `deploy/.env`, which `deploy/setup.sh` creates from `deploy/.env.example`. Docker Compose passes them to the `api` and `worker` containers. The two services share one environment block, so a variable set once applies to both.

<Note>
Compose passes unset optional variables as empty strings. The containers treat an empty value as "not set", so leaving a line blank is the same as removing it.
</Note>

After editing `deploy/.env`, apply the change with:

```bash
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d
```

Passwords must be URL-safe (hex or alphanumeric) because they are embedded in connection URLs.

## Public address and URLs

| Variable | Default | Required | Meaning | Example |
|---|---|---|---|---|
| `SITE_ADDRESS` | `localhost` | Yes | Domain Caddy serves. A real domain gets automatic HTTPS, `localhost` uses a local test CA, `:80` is plain HTTP. | `app.example.com` |
| `APP_URL` | `https://$SITE_ADDRESS` | No | Canonical dashboard URL used in emails, invitation links and OAuth redirects. | `https://app.example.com` |
| `PUBLIC_API_URL` | same origin as the dashboard | No | Base URL of the API as seen by widgets and as shown in webhook URLs. Needed only for split deployments. | `https://api.example.com` |
| `WIDGET_SCRIPT_URL` | `/widget.js` | No | URL of the widget bundle embedded on customer sites. Pin a release with `/widget.<hash>.js` (hash in `/widget.version`). | `/widget.js` |
| `DASHBOARD_API_URL` | empty (same-origin `/api`) | No | API URL given to the dashboard container at start. Must be a plain `http(s)://host[:port]`. Passed to the container as `API_URL`. | `https://api.example.com` |

## Secrets

`deploy/setup.sh` generates all of these. Never commit `deploy/.env`.

| Variable | Default | Required | Meaning | Example |
|---|---|---|---|---|
| `POSTGRES_PASSWORD` | none | Yes | Password of the database owner role `yulona_owner`. Used only by the one-shot `migrate` and `create-tenant` services and the `postgres` container. | 48 hex characters |
| `APP_DB_PASSWORD` | none | Yes | Password of the runtime role `yulona_app` (no `BYPASSRLS`) used by `api` and `worker`. Applied once, when the database is first created. | 48 hex characters |
| `REDIS_PASSWORD` | none | Yes | Password for Redis. | 48 hex characters |
| `JWT_SECRET` | none | Yes | HS256 signing key for access tokens. At least 32 characters, high entropy, no placeholder words such as `change`, `secret` or `test`. Rotating it signs everyone out. | `openssl rand -hex 48` |
| `ENCRYPTION_KEY` | none | Yes for channels, webhooks, calendars, tool connections | AES-256 master key, base64 of 32 bytes. Encrypts channel credentials, webhook signing secrets, OAuth tokens and provider keys. Losing or changing it makes them unreadable. Without it those features answer `503`. | `openssl rand -base64 32` |

See [Security hardening](/self-hosting/security-hardening#encryption-key) before you rotate any of these.

## Deployment mode and behaviour

| Variable | Default | Required | Meaning | Example |
|---|---|---|---|---|
| `DEPLOYMENT_MODE` | `selfhosted` in compose (`saas` if the API runs without compose) | No | `selfhosted`: one workspace, no billing, no credits, signup closed. `saas`: multi-tenant with billing and platform admin. | `selfhosted` |
| `SUPER_ADMIN_ENABLED` | empty (follows mode) | No | Empty means off for `selfhosted` and on for `saas`. Set `true` or `false` to override. | `true` |
| `ALLOW_PUBLIC_SIGNUP` | `false` | No | Open registration. Honoured only when `DEPLOYMENT_MODE=saas`. | `false` |
| `CORS_ORIGINS` | empty (same origin only) | No | Comma-separated origins allowed to call the API cross-origin. `*` is refused in production. | `https://app.example.com` |
| `CROSS_SITE_COOKIES` | `false` | No | Set `true` only when dashboard and API are on different sites (not subdomains of one domain). Sets the refresh cookie to `SameSite=None; Secure`. | `false` |
| `LOG_LEVEL` | `info` | No | `debug`, `info`, `warn`, `error` or `silent`. | `info` |
| `OPENAPI_ENABLED` | `false` in compose | No | Publishes the API reference at `/docs`. Requires `DOCS_PASSWORD` in production. | `false` |
| `DOCS_USERNAME` | `docs` | No | HTTP basic-auth user for `/docs`. 1 to 64 characters, no `:`. | `docs` |
| `DOCS_PASSWORD` | none | When `OPENAPI_ENABLED=true` | HTTP basic-auth password for `/docs`. At least 16 characters, high entropy. | `openssl rand -base64 24` |

## AI provider

Full guidance is in [AI providers](/self-hosting/ai-providers).

| Variable | Default | Required | Meaning | Example |
|---|---|---|---|---|
| `AI_PROVIDER` | empty | No | `openai` (any OpenAI-compatible endpoint), `deepseek`, or `mock` (offline canned answers, demos only). Empty means `openai` when `AI_API_KEY` is set, otherwise `mock`. | `openai` |
| `AI_API_KEY` | none | For a real model | API key sent to the provider. Optional only when `AI_AUTH_SCHEME=none`. | `sk-...` |
| `AI_BASE_URL` | `https://api.openai.com/v1` (`https://api.deepseek.com` for `deepseek`) | No | Base URL of an OpenAI-compatible server. | `http://ollama:11434/v1` |
| `AI_MODEL` | `gpt-4o-mini` (`deepseek-chat` for `deepseek`) | No | Default model name sent in requests. | `gpt-4o-mini` |
| `AI_AUTH_HEADER` | `Authorization` | No | Header that carries the key. | `api-key` |
| `AI_AUTH_SCHEME` | `bearer` | No | `bearer` sends `Bearer <key>`, `raw` sends the key as is, `none` sends no auth header. | `raw` |
| `AI_EXTRA_HEADERS` | none | No | JSON object of extra headers. Values must be strings. | `{"x-org":"abc"}` |
| `AI_QUERY` | none | No | JSON object of query-string parameters added to every request. | `{"api-version":"2024-06-01"}` |
| `AI_CHAT_PATH` | `/chat/completions` | No | Path appended to the base URL. | `/openai/deployments/my-gpt/chat/completions` |
| `CREDITS_EXHAUSTED_MESSAGE` | built-in text | No | Hosted product only. Message customers see when a workspace's AI credits run out. Ignored when self-hosted. | `We will be right back.` |

## Email (SMTP)

With `SMTP_HOST` empty, emails (invitations, notifications) are only written to the log.

| Variable | Default | Required | Meaning | Example |
|---|---|---|---|---|
| `SMTP_HOST` | none | No | SMTP server host. Enables email sending. | `smtp.example.com` |
| `SMTP_PORT` | provider default | No | SMTP port. | `587` |
| `SMTP_USER` | none | No | SMTP username. | `apikey` |
| `SMTP_PASS` | none | No | SMTP password. | `...` |
| `SMTP_SECURE` | `false` | No | `true` for implicit TLS (usually port 465). Any other value means STARTTLS or plain. | `true` |
| `EMAIL_FROM` | `Yulona <no-reply@localhost>` | No | From address. | `Acme <no-reply@example.com>` |

## Object storage (S3 and MinIO)

Storage is used only when `S3_BUCKET`, `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` are all set. Otherwise files are kept in memory and are lost on restart.

| Variable | Default | Required | Meaning | Example |
|---|---|---|---|---|
| `S3_ENDPOINT` | AWS S3 | No | Custom endpoint for MinIO or other S3-compatible services. | `http://minio:9000` |
| `S3_BUCKET` | none | For durable storage | Bucket name. | `yulona` |
| `S3_REGION` | none | No | Bucket region. | `us-east-1` |
| `S3_ACCESS_KEY_ID` | none | For durable storage | Access key id. | `yulona` |
| `S3_SECRET_ACCESS_KEY` | none | For durable storage | Secret access key. | `...` |
| `MINIO_ROOT_USER` | `yulona` | With the `minio` profile | MinIO root user. Reuse it as `S3_ACCESS_KEY_ID`. | `yulona` |
| `MINIO_ROOT_PASSWORD` | generated by setup | With the `minio` profile | MinIO root password. Reuse it as `S3_SECRET_ACCESS_KEY`. | 32 hex characters |

## Licence

| Variable | Default | Required | Meaning | Example |
|---|---|---|---|---|
| `LICENSE_KEY` | none | No | Signed licence token (a JWT). | `eyJ...` |
| `LICENSE_PUBLIC_KEY` | none | With `LICENSE_KEY` | PEM of the vendor public key. Use `\n` for newlines. | `-----BEGIN PUBLIC KEY-----\n...` |

| `YULONA_API_IMAGE` | `yulona/api:local` (built from the repo) | No | API, worker and one-shot image. Use pinned tags or digests. | `ghcr.io/your-org/yulona-api:1.0.0` |
| `YULONA_DASHBOARD_IMAGE` | `yulona/dashboard:local` | No | Dashboard image. | `ghcr.io/your-org/yulona-dashboard:1.0.0` |

## Other settings the API reads

These are not in `deploy/.env.example` and the bundled compose file does not forward them. To use one, add it to the `x-api-env` block in `deploy/docker-compose.yml` and to `deploy/.env`.

| Variable | Default | Meaning |
|---|---|---|
| `DB_POOL_MAX` | `10` | API database pool size (1 to 100). |
| `BODY_LIMIT_BYTES` | `1048576` | Maximum JSON request body (minimum 1024). Knowledge file uploads allow 11 MB. |
| `REFRESH_TOKEN_TTL_DAYS` | `30` | Refresh-token lifetime (1 to 90). Access tokens last 15 minutes. |
| `WIDGET_SESSION_TTL_HOURS` | `24` | Widget visitor session lifetime (1 to 168). |
| `WORKER_CONCURRENCY` | `5` | Jobs the worker runs in parallel. |
| `WORKER_POLL_MS` | `1000` | How often the worker polls for jobs. |
| `WORKER_DB_POOL_MAX` | `10` | Worker database pool size. |
| `STRIPE_PRICE_<PLAN>` | none | Hosted product only. Stripe price id per paid plan, for example `STRIPE_PRICE_PRO`. |
| `BILLING_GRACE_DAYS` | `7` | Hosted product only. Days of grace after a failed payment. |

The compose file sets `NODE_ENV=production`, `PORT=3000` and `TRUST_PROXY=true` for you. `TRUST_PROXY` makes the API read the client IP from the proxy header, which is correct only behind Caddy.

## Rate limits (fixed in code)

These are not configurable by environment variable. They apply per client IP unless noted.

| Limit | Value |
|---|---|
| Global API | 300 requests per minute |
| Login, per IP and email | 8 per 15 minutes |
| Login, per IP | 40 per 15 minutes |
| Registration | 10 per hour |
| Token refresh | 60 per minute |
| `/docs` (basic auth) | 30 per 15 minutes |
