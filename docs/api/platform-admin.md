# Platform admin API (`apps/admin-api`, wave 6)

Contract for the separate platform-admin service. `apps/admin-web` is built from this file. The service is **not** part of the customer API: own process (default port `4100`), own JWT secret, own DB role (`yulona_admin`), own cookie, own origin. The customer API no longer serves `/api/v1/admin/*`.

Base URL: `ADMIN_API_URL` (dev `http://localhost:4100`), every route is under `/api/v1`. JSON in/out (`Content-Type: application/json` on bodies), strict bodies (unknown keys are a `400`). Machine-readable spec: `docs/admin-openapi.json` (generated by `apps/admin-api/scripts/export-openapi.ts`).

## Conventions

- **Errors** (same envelope as the customer API): `{ "error": { "code", "message", "requestId", "details"? } }`.
  Codes: `unauthorized` (401), `invalid_credentials` (401), `invalid_refresh_token` (401), `forbidden` (403, wrong role or IP not allowed), `session_restricted` (403, see Restricted sessions), `csrf_failed` (403), `not_found` (404), `conflict` (409), `validation_error` (400, `details: [{path, message}]`), `unsupported_media_type` (415), `rate_limited` (429, `Retry-After` header), `service_unavailable` (503), `internal_error` (500).
- **Auth**: `Authorization: Bearer <accessToken>` (15 min, HS256 with `ADMIN_JWT_SECRET`, held in memory). A tenant (customer) token is never valid here and an admin token is never valid on the customer API.
- **Session survives reload**: the refresh token is an httpOnly cookie `yl_admin_rt` (`SameSite=Strict`, `Path=/api/v1/auth`, `Secure` in production, 7 days, rotated on every refresh). On page load call `POST /auth/refresh`.
- **Cookie endpoints** (`/auth/refresh`, `/auth/logout`) need the header `X-Admin-Request: 1` (else `403 csrf_failed`); send `credentials: "include"` from the admin web origin (CORS allows only `ADMIN_WEB_ORIGIN`).
- **Roles**: `owner`, `support`, `billing`. Each route below lists the allowed roles (`all` = owner, support, billing). A role is re-read from the DB on every request, so role changes and deactivation apply at once. Wrong role: `403 forbidden`.
- **Rate limits** per admin: reads 30/min, writes (POST/PUT/PATCH/DELETE) 10/min, exports count as writes; login per IP and per IP+email (see Auth). `429` carries `Retry-After`. (Env: `ADMIN_RATE_READ`, `ADMIN_RATE_WRITE` override.)
- **Pagination**: `limit` (1-200, default 50) and `offset`; lists return `{ items, total, limit, offset }`.
- Dates are ISO 8601 UTC strings. Money is integer cents; credits are micro-credits (`1 credit = 1_000_000`) where a field name ends in `Micro`.
- **No customer content**: no message text, contact name/email/phone, secrets or ciphertext is ever returned. Reading customer conversations requires an audited impersonation.
- **Read audit**: `GET /tenants/:id` (action `tenant.view`) and the exports (`tenant.export`, `customers.export`, `errors.export`) write a platform audit row, debounced to one per admin + tenant + action per 10 minutes.

### Health object (used by lists and detail)

```json
{ "score": 72, "bucket": "watch", "reasons": [ { "code": "failed_webhooks", "label": "4 failed webhook deliveries in 7 days", "points": 12 } ] }
```
`score` = 100 minus the penalties (floor 0); `bucket`: `healthy` (80+), `watch` (50-79), `at_risk` (below 50). Reason codes and maximum penalty: `failed_jobs` 20, `failed_webhooks` 15, `channel_errors` 20, `failed_ingests` 10, `credits_exhausted` 25, `credits_low` 10 (under 10% left), `payment_failed` 25, `inactive` 15 (no customer messages for 14+ days), `no_published_agent` 10, `abuse_blocks` 10. `reasons` is sorted by `points` descending (top reasons first).

## Auth (`/auth/*`)

| Method and path | Roles | Body / query | Response |
|---|---|---|---|
| `POST /auth/login` | public | `{ email, password }` | `Session` or `{ twoFactorRequired: true, challengeToken, expiresIn: 300 }` |
| `POST /auth/login/2fa` | public | `{ challengeToken, code }` or `{ challengeToken, recoveryCode }` | `Session` |
| `POST /auth/refresh` | cookie | none (header `X-Admin-Request: 1`) | `Session` (rotates the cookie) |
| `POST /auth/logout` | cookie | none (header `X-Admin-Request: 1`) | `{ ok: true }` (revokes the session, clears the cookie) |
| `GET /auth/me` | all | | `Me` |
| `POST /auth/password` | all | `{ currentPassword, newPassword }` | `{ ok: true }` (revokes all other sessions) |
| `POST /auth/2fa/setup` | all | `{ password }` | `{ secret, otpauthUrl }` (pending until confirmed) |
| `POST /auth/2fa/confirm` | all | `{ code }` | `{ recoveryCodes: string[10] }` (shown once) |
| `POST /auth/2fa/disable` | all | `{ password, code }` (or `recoveryCode`) | `{ ok: true }`; `403 forbidden` when `ADMIN_REQUIRE_2FA=true` |

`Session` = `{ accessToken, expiresIn: 900, admin: Me }`. `Me` = `{ id, email, name, role, twoFactorEnabled, restricted: null | "password_change" | "two_factor_enrolment" }`.

- Login: 5 failures lock the account with growing back-off (30 s up to 15 min); the response is always `invalid_credentials` (no user enumeration). IP limit 40 per 15 min, IP+email limit 8 per 15 min, 2FA step 8 per 15 min.
- 2FA (TOTP, RFC 6238: SHA-1, 6 digits, 30 s, +-1 step) is asked only when the admin enrolled. `ADMIN_REQUIRE_2FA` (default `false`) is ready for later: when `true`, an admin without 2FA gets a **restricted session**.
- Recovery codes: 10 single-use codes (`xxxxx-xxxxx`), stored hashed; a used code is consumed.
- Restricted sessions: `Me.restricted` is set after login when the password must be changed (new admins, owner reset) or when 2FA enrolment is required. Only `/auth/me`, `/auth/password`, `/auth/2fa/setup|confirm`, `/auth/logout`, `/auth/refresh` work; everything else returns `403 session_restricted` with `details: { reason }`.
- A suspended/deactivated admin loses all sessions immediately.

## Impersonation (one-time code)

| Method and path | Roles | Notes |
|---|---|---|
| `POST /tenants/:id/impersonate` | owner, support (write mode: owner only) | `{ reason (5-500), userId?: uuid, readOnly?: boolean }`. `readOnly` defaults to `true`; `readOnly:false` needs role `owner` (else `403`). Response `201`: `{ sessionId, code, codeExpiresIn: 60, customerUrl, readOnly, user: { id, email, name, role }, tenant: { id, name } }`. `customerUrl` = `<ADMIN_CUSTOMER_APP_URL>/impersonate#code=<code>` (fragment, so the code never reaches a server log). The admin web opens it in a new tab. |
| `POST /impersonation/:sessionId/end` | owner, support | `{ ok: true }` (404 if already ended); billing cannot impersonate |
| `GET /impersonations?tenantId&adminId&limit&offset` | all | platform-wide history `{ items: ImpersonationRecord[], total }` |

Customer side (only coupling): `POST /api/v1/auth/impersonation/exchange { code }` on the customer API redeems the code (single use, 60 s TTL, stored hashed) and returns `{ accessToken, expiresIn, sessionId, readOnly, user, tenant }`; the token lives 15 minutes (counted from the exchange), carries a `ro` claim when read-only, and the customer API rejects every non-`GET`/`HEAD` request made with a read-only token (`403 forbidden`). A wrong, used or expired code is `400 validation_error`. The admin-api never holds a tenant signing key.

## Security headers and network

Every response: `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, HSTS in production. CORS: only `ADMIN_WEB_ORIGIN`, credentials allowed. `ADMIN_ALLOWED_CIDRS` (comma separated IPv4/IPv6 CIDRs, empty = allow all) is enforced on every request using the client IP (with `TRUST_PROXY=true`, the rightmost `X-Forwarded-For` entry, as in the customer API); a rejected IP gets `403 forbidden` (health is exempt only from the CIDR check: `GET /healthz`, `GET /readyz`).

## Environment

`ADMIN_JWT_SECRET` (required, >= 32 chars, must differ from `JWT_SECRET`; startup aborts otherwise), `ADMIN_DB_URL` or `ADMIN_DB_PASSWORD` (+ `DATABASE_URL` host/db), `ADMIN_WEB_ORIGIN`, `ADMIN_ALLOWED_CIDRS`, `ADMIN_REQUIRE_2FA` (default `false`), `ADMIN_CUSTOMER_APP_URL`, `ADMIN_PORT`/`PORT` (4100), `ADMIN_RATE_READ`, `ADMIN_RATE_WRITE`, `ENCRYPTION_KEY` (provider credentials and TOTP secrets), `DEPLOYMENT_MODE`, `TRUST_PROXY`, `REDIS_URL`, `LOG_LEVEL`, email provider variables (invitation resend).
